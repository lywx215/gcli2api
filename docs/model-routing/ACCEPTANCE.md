## 实现范围

每个实际生成请求只读取一次新鲜路由配置，捕获一个不可变的策略和功能快照。
前缀处理后，CLI 精确匹配公开名并保留已有后缀派生；反重力只精确匹配完整名，
不从一个公开名自动生成 `-search` 或思考档位。转换与规范化使用目标家族的实际规则，
不是直接覆盖规范化后的模型。重试和续传保持首个请求的目标和快照。

目录先验证配置再获取动态数据。动态目录与准入证明隔离，空表投影保持原有字段和顺序。
启用的目标及其被接管空间被隐藏，公开项使用重新生成的描述；没有把本地证明当成
上游 availability 验证。未知来源或不支持的规则安全拒绝。

成功响应只改明确协议身份位置，统一回显客户端完整请求名：Gemini 根部及已有
`response` 包装的 `model` / `modelVersion`，OpenAI 顶层与流式 chunk 的 `model`，
Anthropic message 及 `message_start.message.model`。正文、工具参数、签名、图片和
来源 URL 不作递归字符串替换。用户直接请求原名时可以回显其已提交的原名；
管理员专用配置页可以查看目标，这是权限边界内的预期行为。

设置页保留双渠道草稿，保存时提交整表。配置键只能通过既有认证的专用接口读写；
通用 GET 不返回整键，通用 SAVE 携带该键时整批拒绝。没有新增 Vertex、模型探测、
名称保护关闭开关，也没有更改管理契约或数据库表。
