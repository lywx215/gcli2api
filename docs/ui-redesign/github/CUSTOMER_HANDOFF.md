## 接收和打开预览

1. 接收主协调给出的固定完整提交或带 SHA256 的构建包，核对版本与文件清单，先保留已有源码和配置。需要源码核对时用独立干净工作树；有目标文件、未提交工作或哈希差异先协调，不能强制覆盖。
2. 按交付包的实际说明打开本地预览。Mac 需要可获取的源码/产物及启动说明，或对 Mac 可达的预览地址；Windows 的 `127.0.0.1` 只属于 Windows 本机，不能作为跨机访问地址。本说明不启动服务、不发布公网预览或部署。
3. 使用主协调提供的合成账号、假文件及安全结果确认界面，保留版本标识。确认素材中不包含真实凭证、密码、登录缓存、授权状态或数据库；本轮不做真实 OAuth、业务模型生成或生产数据操作。
4. 按人工清单覆盖六页和全局入口，桌面、手机各走主要流程即可。实际确认人填写通过项、问题和未执行项；无法访问、尚未挂载或受依赖阻塞的项目写“未确认/阻塞”。提供预览、代码或截图均不等于客户签字。
