# Antigravity 人工测试与自动保护分离

2026-09-29，按已由 Claude 批准的 v10 方案实施。

## 行为

- 已认证面板的模型测试、消息测试、批量测试、额度查询/刷新、项目检验使用指定凭证直接请求。
  冷却、异常额度组、禁用和永久禁用不阻止这些人工请求；面板身份认证仍然有效。
- 保留旧 fork 的请求：指定模型使用固定标记和256输出token；默认连通测试使用hi及1输出token。
  额度刷新只查询Google额度，不添加生成请求、换凭证或恢复探测。
- 成功恢复被测额度组，其他组不变；成功测试及项目检验均不自动开启禁用凭证。
  真实失败仍可按现有自动禁用配置更新，但本地校验失败和回写失败不触发禁用。
- 额度正值恢复对应组；明确零优先，保留有效冷却或按有效reset/原配置补冷。
  已返回但缺失/非法的额度为未知，正值与未知混合时不整组解冷；完全未返回的模型遵循组级恢复规则。
  滚动168小时不能否决人工正额度恢复；正常组不会因人工测试新增异常状态。
- “解除异常拦截”仍保留计时冷却。明确启用/禁用动作保持原行为，与测试成功分开。

## 结果

人工HTTP响应保留实际收到的Google状态。HTTP200中的错误、退役通知或无效回复仍会显示
`success=false`，但不会伪装成Google424/502/503。错误、日志和持久错误字段不回传原文或原生模型名。

新增字段：`upstream_status`、`response_source`、`phase`/`phases`、`verified_reply`、`state_update`。
界面分别展示Google响应、本地验证以及状态更新。Google成功但回写冲突时仍保留成功结果，
同时显示状态未更新。批量结果逐项保留这些信息。

凭证代次、内容版本和目标状态快照限制回写，不能覆盖替换凭证或较新的冷却。
并发Token刷新只可复用同代且稳定身份字段一致的有效Token。旧记录复用既有方法初始化代次，
损坏额度状态不阻止请求；统计、错误、冷却、周期统计分别报告更新结果。

## 兼容和范围

- 来源参数只由服务端认证入口设置，默认`legacy`，且只有Antigravity模式才能进入人工分支。
- 正常模型API、自动保护和Management旧调用保持当前规则；Gemini CLI没有专属改造。
- Management schema/capability不变，不新增数据库字段，无迁移或manager侧配套动作。
- 两个诊断脚本调用面板额度接口也会触发人工恢复。模型目录验证默认操作临时实例，
  `--live-url`和额度测量脚本操作指定服务；源SQLite只读不代表目标服务状态只读。
- 回滚代码不会恢复已经发生的人工状态更新，不能通过清空额度数据回滚。

## 验证边界

测试使用模拟Google、合成凭证、临时SQLite和PostgreSQL/MySQL/MongoDB驱动替身；
不连接生产数据库或真实Google接口。前端验证包含Node语法检查及模拟UI调用的结果分层断言。
最新测试数量和交付状态见本次交付记录。方案批准不代表实现已经通过Claude代码审核。
