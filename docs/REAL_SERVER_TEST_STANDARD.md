# 实际服务器测试规范

## 1. 目的与适用范围

本文是 gcli2api 的固定实际服务器测试规范。今后只要任务中出现“启动服务并测试”“实际服务器测试”“部署后验证”或同等含义，就必须执行本文全部必选步骤。仅检查端口、模型列表、鉴权或单个模型属于冒烟测试，不能表述为实际服务器测试通过。

实际服务器测试必须对当前代码定义或当前凭证动态暴露的**全部基础模型**逐一发起真实生成请求。不得用健康检查响应、Mock、只读模型列表或本地转换测试替代真实上游推理。

## 2. 基础模型的权威来源

| 模式 | 权威来源 | 纳入规则 |
| --- | --- | --- |
| GeminiCLI | `src/utils.py` 的 `BASE_MODELS` | 列表中的每个模型均为必测项 |
| Antigravity | 运行中服务的 `GET /antigravity/v1/models` | 去除 `假流式/`、`流式抗截断/` 前缀后的动态原生模型；保留上游模型名本身携带的 `-high`、`-low`、`-thinking` 等部分 |

功能前缀、thinking/search 本地组合、假流式和流式抗截断不属于“基础模型全量测试”。它们由各自专项回归测试覆盖。新增基础模型后，下一次实际服务器测试必须自动进入测试清单，不得继续使用手工维护的旧报告跳过。

## 3. 标准执行顺序

### 3.1 前置检查

1. 记录当前分支、Git SHA 和工作区状态。
2. 确认服务启动完成，`HEAD /keepalive` 返回 2xx。
3. 确认 API 密钥通过环境变量提供，禁止把真实密钥写入脚本、文档或报告。
4. GeminiCLI 和 Antigravity 每个启用模式都应至少有一个可用凭证。缺少凭证、动态模型列表为空或模型发现失败，必须标记为 `BLOCKED`，整次实际服务器测试不通过。
5. 记录存储引擎、SMART 429 状态和服务版本，便于复现。

### 3.2 基础接口冒烟

至少检查首页、静态资源、版本接口、鉴权的 401/403/200、OpenAI 模型列表、Gemini 模型列表、配置状态和凭证状态。冒烟通过只是进入真实模型测试的前提，不是最终验收结果。

### 3.3 全基础模型真实生成

在项目根目录执行：

```bash
GCLI2API_TEST_API_KEY='<API 密钥>' \
  .venv/bin/python scripts/test_all_base_models.py
```

默认命令同时要求 GeminiCLI 与 Antigravity 完成。只测试单个模式仅用于定位故障，不可作为完整验收：

```bash
GCLI2API_TEST_API_KEY='<API 密钥>' \
  .venv/bin/python scripts/test_all_base_models.py --mode geminicli
```

可通过 `GCLI2API_TEST_BASE_URL` 指向其他实际服务器，通过 `GCLI2API_TEST_TIMEOUT` 调整单模型超时。脚本按模型顺序串行请求，固定使用非流式 OpenAI 兼容接口、最小输出和唯一测试提示，避免并发调度掩盖模型级故障。

测试客户端不继承 `HTTP_PROXY`、`HTTPS_PROXY` 等系统代理变量，确保对本地或明确指定服务器的请求不会被开发机代理重定向。若目标服务器必须经过代理，应先使用受控网络入口，不得临时修改脚本绕过本规范。

每个模型必须满足：

- 已真实执行 `POST /v1/chat/completions` 或 `POST /antigravity/v1/chat/completions`。
- HTTP 状态为 2xx。
- 响应为合法 JSON，存在 `choices[0].message.content`。
- 文本或多模态内容非空。
- 报告记录模式、模型、状态码、耗时、请求 ID、响应模型、内容摘要和内容哈希。

429、5xx、超时、空内容、格式错误均为失败。429 即使表示凭证仍有效，也不能证明该基础模型本次实际生成成功。

### 3.4 本地回归与日志检查

真实模型测试后运行：

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m compileall -q .
git diff --check
```

检查服务日志中是否出现未解释的异常、任务崩溃或资源关闭错误。真实测试可能更新凭证成功/失败统计和冷却状态，这是预期运行时数据；不得因此修改或覆盖凭证代码。

## 4. 报告与判定

脚本在 `.test-results/real-server-models-YYYYMMDD-HHMMSS.json` 生成审计报告。报告不包含 API 密钥和完整上游响应。每次交付至少说明：

- Git SHA、服务地址和服务版本。
- 两种模式发现的基础模型完整清单。
- 每个模型的通过/失败、HTTP 状态和耗时。
- 通过数、失败数、阻塞模式数。
- pytest、compileall、`git diff --check` 结果。
- 未执行项目及原因。

只有 `failed=0` 且 `blocked_modes=0` 时，才能写“实际服务器测试通过”。任一模型失败或任一必需模式阻塞时，应写“实际服务器测试未通过”，并保留报告供排查，不能降级为整体成功。

## 5. 安全与成本约束

- 每个基础模型默认只发起一次最小真实请求，失败时不自动反复消耗额度。
- 不测试功能变体，除非任务另有要求。
- 不在命令历史、日志、报告或 Git 中提交真实密钥、访问令牌和凭证文件。
- 对生产服务器执行前应确认测试请求会产生配额消耗；用户明确要求实际服务器测试即表示允许本规范的一次全基础模型最小请求。
- 脚本不得额外调用禁用、删除或批量测试等凭证管理接口。正常业务请求自身可能更新成功/失败统计、冷却或自动封禁状态，执行后必须检查并报告；需要人工恢复或修改凭证时另行取得明确授权。
