## 2. 起因与现状

### 2.1 问题起因

Google 远端算力不足时会频繁返回 429。当前系统收到 429 后继续重试并随机切换凭证，在以下条件叠加时可能形成请求风暴：

1. 单个客户端请求允许多次重试。
2. 多个客户端并发访问。
3. 凭证选择为随机方式，同一请求可能再次选到已经失败的凭证。
4. 容量类 429 没有有效冷却时，凭证会立即重新进入候选池。
5. 下一凭证预取发生在当前凭证错误状态写入之前，存在确定的陈旧读取窗口；不表述为“必然完成选择”。
6. 首版若运行于多 Worker 或外部多副本，进程内 single-flight、探测锁和熔断状态无法提供全局协调。

结果可能是单个配置被调用数百甚至上千次，进一步触发 Google 风控。如果简单地在 429 时禁用凭证，又可能导致全部凭证退出号池并直接把“无可用凭证”返回给客户端，因此必须同时控制请求放大和号池可用性。

### 2.2 当前实现证据

当前代码存在以下行为：

- `src/api/geminicli.py` 和 `src/api/antigravity.py` 对 429、500、503 进行重试。
- 429 重试配置默认值不一致：
  - 后端默认最大重试次数为 5。
  - `.env.example` 为 5。
  - README 描述为 3。
  - 前端缺省回填为 20 次、0.1 秒。
- 请求重试时先创建下一凭证预取任务，再记录当前凭证冷却，存在重新选中当前凭证的竞态。
- 当前凭证管理器明确认为 429 不是永久失效，不会自然退出凭证池。
- `MODEL_CAPACITY_EXHAUSTED` 没有额度重置时间时，当前逻辑不设置模型冷却。
- 消息测试将任何 429 都视为“凭证有效”。
- 额度查询失败目前统一由面板接口转换为 HTTP 400，没有更新凭证健康状态。
- 当前随机选择接口没有“本次请求已失败凭证”的排除参数。

### 2.3 已确认的风控样本

当前实际凭证额度查询日志出现：

```text
HTTP 429
{
  "error": {
    "code": 429,
    "message": "Resource has been exhausted (e.g. check quota).",
    "status": "RESOURCE_EXHAUSTED"
  }
}
```

该响应没有 `details`、`reason`、额度重置时间或模型信息。按照当前实际账号行为，该额度查询结果代表账号被风控。

现有页面仍显示“已启用、无错误”，说明当前状态模型无法表达凭证级风控。

### 2.4 与模型算力不足的区别

Google 模型算力不足的已知响应为：

```json
{
  "error": {
    "code": 429,
    "message": "No capacity available for model gemini-3.1-pro-preview on the server",
    "status": "RESOURCE_EXHAUSTED",
    "details": [
      {
        "@type": "type.googleapis.com/google.rpc.ErrorInfo",
        "reason": "MODEL_CAPACITY_EXHAUSTED",
        "domain": "cloudcode-pa.googleapis.com",
        "metadata": {
          "model": "gemini-3.1-pro-preview"
        }
      }
    ]
  }
}
```

该错误属于模型或服务器容量不足，不能将凭证判定为风控账号。

## 3. 设计目标

1. 阻止单个客户端请求产生不受控的上游重试。
2. 明确区分模型容量不足、额度耗尽、凭证风控和未知错误。
3. 风控判断只以 GeminiCLI 额度查询结果为准。
4. 被风控凭证退出生产池，但不自动永久禁用。
5. 提供低频恢复检查，避免永久丢失后续恢复的账号。
6. 所有新行为必须由默认关闭的总开关控制。
7. 关闭总开关后完整恢复当前旧逻辑。
8. 即使策略存在误判，也能从控制面板紧急停止，不需要重启。
9. 首版只允许单进程、单副本部署；多 Worker 时保护必须拒绝启动。
10. 全池暂时不可用时返回明确、可重试的客户端错误。

## 4. 非目标

- 不在启动时扫描全部现有凭证。
- 不在列表刷新时请求 Google。
- 不在每次成功请求后查询额度。
- 不使用邮箱、Tier、Project ID 或历史成功率推断风控。
- 不使用 GeminiCLI 额度接口判断 Antigravity 风控。
- 不因为任何 429 自动永久禁用凭证。
- 不在保护策略关闭时改变现有调度结果。
- 不借本次改动修复 MySQL 与其他后端的全部历史字段差异。
- 首版不实现 Redis pub/sub、分布式租约、数据库协调表或数据库轮询。

## 5. 总开关设计

### 5.1 配置定义

新增配置：

```text
数据库键：smart_429_protection_enabled
环境变量：SMART_429_PROTECTION_ENABLED
默认值：false
```

配置缺失、格式非法或读取异常时，结果必须为 `false`。

控制面板显示：

```text
429 分级保护：已停止 / 已启动
```

默认状态为“已停止”。

### 5.2 停止状态语义

开关关闭时：

- 不执行风控额度检查。
- 不写入新的隔离、检测或复检状态。
- 不启动后台复检任务。
- 不执行新增的池级熔断。
- 不执行新增的并发限制和请求排除集合。
- 新上传凭证不进入 `checking`。
- 调度器忽略已有的新增健康状态。
- 原有 429 重试、自动封禁配置和客户端响应保持不变。

这意味着关闭状态是真正的兼容回退，而不是仅停止后台任务。

### 5.3 运行中停止

运行中关闭开关时：

1. 立即刷新当前实例的同步配置缓存。
2. 停止后台复检调度器。
3. 取消尚未开始的检测任务。
4. 释放容量熔断和并发控制状态。
5. 已经发出的 HTTP 请求允许完成，但返回结果写入前必须再次检查开关。
6. 如果开关已经关闭，检测结果不得写入隔离状态。

异步任务需要携带策略版本号；配置版本变化后，旧任务结果全部作废。

### 5.4 单实例硬门槛

- 首版仅支持 SQLite、MySQL、PostgreSQL、MongoDB 的单进程、单副本部署。
- `WORKERS != 1` 时保护保持停止，状态原因为 `multi_instance_unsupported`，服务本身继续运行。
- 外部多副本无法自动识别，明确列为不支持部署。
- single-flight、探测锁、限流器、容量熔断均使用进程内异步原语。
- 健康与隔离状态持久化，进程重启后恢复；进行中的任务不恢复。

### 5.5 历史隔离状态

关闭开关只旁路状态，不自动删除数据。

重新启动后，已有隔离状态重新生效。管理界面提供独立的“清除全部 429 保护状态”操作，并要求二次确认。

系统不得因为健康凭证数量降至零而自动关闭保护，否则会重新使用已确认风控的账号。是否紧急回退由管理员决定。

## 6. 429 分类规则

判断顺序必须完全互斥：

1. 存在 `QUOTA_EXHAUSTED`、额度重置时间或重置延迟：`quota_exhausted`。
2. `reason` 精确为 `MODEL_CAPACITY_EXHAUSTED` 或 `NO_CAPACITY_AVAILABLE`：`model_capacity_exhausted`。
3. GeminiCLI 的其他 429：`risk_check_required`，只触发一次独立额度查询。
4. 无法识别的非 GeminiCLI 429：`indeterminate`。

`RESOURCE_EXHAUSTED` 本身不是容量原因。额度风控核验不得调用或复用 `parse_quota_reset_timestamp()`；额度接口中精确通用 message 匹配时，笼统 `reason=RESOURCE_EXHAUSTED` 不构成冲突。

| 分类 | 判断依据 | 处理 |
| --- | --- | --- |
| 正常账号 | GeminiCLI 额度接口 HTTP 200 且响应可解析 | 保持或恢复 `healthy` |
| 风控账号 | 额度接口精确返回指定通用 429 | 凭证级长期隔离 |
| 模型容量不足 | `reason=MODEL_CAPACITY_EXHAUSTED` | 模型级秒级冷却 |
| 额度耗尽 | `reason=QUOTA_EXHAUSTED` 或存在额度重置时间 | 冷却到重置时间 |
| 认证失效 | 明确的 400/401/403、refresh token 失效 | 沿用认证失效处理 |
| 状态不确定 | 网络错误、5xx、未知格式 429、无法解析响应 | 不判定风控 |

### 6.1 风控精确匹配

额度查询结果必须同时满足：

```text
HTTP status 或 error.code = 429
error.status = RESOURCE_EXHAUSTED
规范化后的 error.message =
Resource has been exhausted (e.g. check quota).
```

规范化只允许：

- 去除首尾空白。
- 允许末尾有或没有一个句点。
- 不进行宽泛的 `contains("quota")` 判断。

不同错误文本不能直接判定风控，只能返回 `indeterminate`。

### 6.2 额度为零

额度接口正常返回但部分模型 `remaining=0` 时：

- 账号仍是正常账号。
- 只为额度为零的具体模型写入模型冷却。
- 优先使用接口返回的重置时间。
- 没有有效重置时间时沿用四小时兜底。
- 不设置凭证级风控隔离。

## 7. 风控检测触发条件

保护开关启动后，只在以下场景查询额度：

1. 业务请求返回没有明确 capacity/quota details 的通用 429。
2. 管理员点击“查看额度”。
3. 管理员点击“立即复检”。
4. 已隔离凭证到达计划复检时间。

新凭证上传后不自动查询额度，避免批量上传立即形成大量 Google 请求。首次业务异常或管理员操作时再按需检测。

### 7.1 单次检测约束

- 同一凭证同时只能执行一次额度查询。
- 多个并发业务请求必须共享同一个检测结果。
- 当前业务请求不等待长时间检测；它可以在重试预算内切换其他凭证。
- 检测期间凭证状态为 `checking`，保护开关启动时暂时不可选。
- 检测超过 60 秒视为超时，恢复到检测前状态并进入 5 分钟检测退避。
- 首版使用进程内 single-flight；单进程、单副本是发布硬门槛。

## 8. 凭证健康状态机

新增健康状态：

| 状态 | 含义 | 是否可用于生产请求 |
| --- | --- | --- |
| `healthy` | 正常或尚未发现风控 | 是 |
| `checking` | 正在进行额度风控检查 | 否 |
| `risk_quarantined` | 已确认风控，等待低频复检 | 否 |
| `manual_review` | 多次复检仍风控，等待人工处理 | 否 |

状态流转：

```text
healthy
  ├─ 明确容量不足 → 保持 healthy，仅设置模型冷却
  ├─ 明确额度耗尽 → 保持 healthy，仅设置模型冷却
  └─ 通用/模糊 429 → checking
                         ├─ 额度正常 → healthy
                         ├─ 精确风控 429 → risk_quarantined
                         └─ 状态不确定 → healthy + 5 分钟检测退避

risk_quarantined
  ├─ 额度正常 → healthy
  ├─ 相同风控 429 → 推进复检阶段
  └─ 状态不确定 → 保持当前阶段，1 小时后重试

第三个自动复检阶段仍风控
  → manual_review
```

关闭总开关时，调度器忽略该状态机并按旧逻辑运行。

## 9. 风控隔离与恢复

### 9.1 复检周期

| 阶段 | 下次额度查询 |
| --- | --- |
| 首次确认风控 | 24 小时后 |
| 第一次复检仍风控 | 3 天后 |
| 第二次复检仍风控 | 7 天后 |
| 第三次复检仍风控 | 转人工复核，停止自动请求 |

任意一次额度查询正常返回后，立即恢复 `healthy` 并清除隔离阶段。

### 9.2 非风控失败

复检遇到以下情况不能推进风控阶段：

- 网络连接失败。
- 请求超时。
- HTTP 5xx。
- 未知格式 429。
- `MODEL_CAPACITY_EXHAUSTED`。
- 明确额度耗尽。

网络和临时服务异常在 1 小时后重试当前阶段；额度耗尽延迟到额度重置后再检查。

### 9.3 后台调度限制

- 扫描周期：60 秒。
- 全局默认并发：2。
- 启动速率：每秒最多一个额度查询。
- 同一凭证使用进程内 single-flight 合并并发检查。
- 关闭总开关后不得领取新任务。
- 任务完成写状态前再次校验开关和策略版本。

## 10. 模型容量不足保护

保护开关启动时，`MODEL_CAPACITY_EXHAUSTED` 使用模型级软冷却：

```text
第一次：2 秒
第二次：4 秒
第三次：8 秒
第四次：16 秒
后续：最多 30 秒
```

每次加入 ±20% 随机抖动。对应模型成功一次后清除连续容量失败计数。

容量状态按“模式 + 实际上游模型”归一化，不能使用可能变化的客户端模型别名作为键。

### 10.1 池级熔断

以下任一条件触发池级熔断：

- 最近 10 秒至少 10 个样本、容量 429 比例达到 80%，并且连续两个 10 秒窗口均满足。
- 当前模型所有合格凭证都处于容量软冷却。

熔断从 5 秒开始，连续失败时增加到最多 30 秒。半开期间每个模式和模型只允许一个探测请求。

## 11. 请求级重试保护

开关启动时：

- 单请求最多产生三次上游调用，包括第一次请求。
- 同一请求不得重复选择已经失败的凭证。
- 凭证管理接口增加 `excluded_credentials` 参数。
- 重试间隔采用 0.5 秒、1.5 秒递增退避并加入抖动。
- 必须先记录冷却、检测或隔离状态，再预取下一凭证。
- 移除当前重复 sleep，保证一次重试只等待一次。
- 流式与非流式请求使用同一重试决策对象。
- GeminiCLI 与 Antigravity 共用容量保护，但风控额度判断只用于 GeminiCLI。

现有 `RETRY_429_*` 配置继续存在且不修改旧默认值。保护启动时使用独立的 `smart_429_max_attempts=3`（范围 1–5）和 `smart_429_retry_base_interval=0.5`（范围 0.1–5 秒）；关闭时保持旧行为。Antigravity 继续只把 429、503 作为内建可重试状态，不新增 500。

## 12. 全池不可用处理

### 12.1 容量暂时不足

所有凭证处于容量冷却时：

- 服务端最多等待 8 秒。
- 冷却到期或半开探测成功后继续处理。
- 超时返回：

```text
HTTP 503
error.type = upstream_capacity_exhausted
Retry-After = 最早允许重试的秒数
```

### 12.2 全部被风控隔离

所有合格凭证均为 `risk_quarantined` 或 `manual_review` 时返回：

```text
HTTP 503
error.type = credential_pool_quarantined
Retry-After = 最早计划复检时间
```

客户端响应不得包含凭证文件名、邮箱、Project ID 或风控账号数量。

### 12.3 保护关闭

总开关关闭后，上述新响应全部旁路，恢复当前返回逻辑。

## 13. 数据模型与存储迁移

新增字段：

| 字段 | 类型 | 默认值 |
| --- | --- | --- |
| `health_status` | 字符串 | `healthy` |
| `quarantine_reason` | 字符串/空 | `null` |
| `probe_stage` | 整数 | `0` |
| `next_probe_at` | 时间戳/空 | `null` |
| `last_health_check_at` | 时间戳/空 | `null` |
| `health_check_started_at` | 时间戳/空 | `null` |
| `health_state_version` | 整数 | `0` |

要求：

- SQLite、MySQL、PostgreSQL 分别幂等加列，MongoDB 使用缺省字段兼容；字段仅用于 GeminiCLI。
- 旧数据迁移后必须保持 `healthy`，不能自动隔离。
- 新字段迁移可以在总开关关闭时安全部署。
- 所有查询和摘要接口必须兼容字段不存在的旧数据。
- MySQL 只扩展新增健康字段相关的 `STATE_FIELDS`、投影、摘要与更新，不依赖缺失的历史统计字段。
- Antigravity 不迁移健康字段，对外需要时计算为 `healthy`。
- 启动时检查必要字段的读写能力；失败时保护保持停止并显示原因，服务继续运行。
- 四个后端以及 MySQL/MongoDB 的 Redis 候选列表只有在保护启动时才排除非健康或请求内已失败凭证。
- 关闭保护时不得为恢复可用池而批量改写数据库。

## 15. 管理 API 变化

### 15.1 配置接口

`GET /config/get` 增加：

```json
{
  "smart_429_protection_enabled": false
}
```

`POST /config/save` 接受布尔值，并在保存后启动或停止后台服务。

### 15.2 额度接口

`GET /creds/quota/{filename}` 在保护启动且识别为风控时返回结构化业务结果，不再只返回笼统 HTTP 400：

```json
{
  "success": false,
  "risk_controlled": true,
  "health_status": "risk_quarantined",
  "next_probe_at": 0,
  "error": "账号额度接口返回风控状态"
}
```

原始 Google 响应只写入受控错误记录，不向普通客户端暴露。

### 15.3 人工操作

新增或扩展：

- `POST /creds/risk-check/{filename}`：立即执行一次额度复检。
- 单凭证“解除隔离”：恢复 `healthy`，不发送 Google 请求。
- 单凭证“永久禁用”：沿用现有永久禁用语义。
- 批量“清除 429 保护状态”：必须带显式确认参数。

## 16. 前端变化

桌面端和移动端同步增加：

- 总开关，默认“已停止”。
- 启动时的风险说明。
- 环境变量锁定显示。
- `检测中`、`风控隔离`、`待人工复核`徽标。
- 最近检测时间和下次复检时间。
- “立即复检”“解除隔离”“永久禁用”操作。
- 启动前展示当前健康、隔离和待复核数量。

当前“429 即凭证有效”的提示需要调整：

- 模型容量 429：显示“远端模型容量不足”。
- 额度查询风控 429：显示“账号已进入风控隔离”。
- 未知 429：显示“状态不确定，未判定风控”。
- 不能继续统一显示“限流中但凭证有效”。

## 17. 兼容与回滚

### 17.1 发布兼容

实施顺序必须保证：

1. 先添加兼容字段。
2. 再部署读取和展示能力。
3. 再部署保护逻辑。
4. 总开关始终保持关闭。
5. 完成测试和人工验证后才允许小范围启动。

### 17.2 紧急回滚

首选回滚方式是关闭总开关：

- 不需要回滚数据库字段。
- 不需要重启服务。
- 不删除隔离历史。
- 所有请求恢复旧调度路径。

如果代码本身影响关闭状态的旧路径，则该版本不得发布。

## 18. 主要风险与缓解

| 风险 | 缓解措施 |
| --- | --- |
| 错误识别导致大量凭证退出池 | 精确额度响应匹配、默认关闭、紧急总开关 |
| 批量检测造成新的风控 | 不做启动扫描、不自动检测上传凭证、全局限速 |
| 并发请求重复查询同一凭证 | 单实例进程内 single-flight、请求级排除集合 |
| 关闭开关后异步任务仍写隔离 | 写入前校验开关与策略版本 |
| 多实例缺少协调 | `WORKERS != 1` 拒绝启动保护，外部多副本文档声明不支持 |
| 重新启动后历史隔离导致池骤减 | 启动前展示预计可用数量、保留手动清除操作 |
| 将容量不足误判为风控 | 优先识别 `MODEL_CAPACITY_EXHAUSTED`，风控只看额度接口 |
| 永久失去可能恢复的账号 | 24 小时、3 天、7 天低频复检 |
| 风控号反复进入生产流量 | 隔离到期后仍需额度复检成功才能恢复 |

## 19. 自动化测试要求

### 19.1 开关回归

- 配置不存在时默认关闭。
- 非法环境变量视为关闭。
- 关闭状态下不产生额度查询。
- 关闭状态下调度结果与当前版本一致。
- 关闭状态下已有隔离记录不影响选取。
- 运行中关闭后，未完成任务不能写状态。
- `WORKERS != 1` 时保护保持停止并返回 `multi_instance_unsupported`。

### 19.2 分类测试

- 额度 HTTP 200 返回 `normal`。
- 精确通用 429 返回 `risk_controlled`。
- 相似但不相同的消息返回 `indeterminate`。
- `MODEL_CAPACITY_EXHAUSTED` 不触发额度风控隔离。
- `QUOTA_EXHAUSTED` 设置额度冷却。
- 网络错误和 5xx 不推进风控阶段。

### 19.3 调度与并发

- 同一请求不重复选择凭证。
- 单请求上游调用不超过三次。
- 数百个并发通用 429 对同一凭证只产生一次额度查询。
- 冷却写入先于下一凭证预取。
- 单实例只有一个半开探针和一个风控复检任务。

### 19.4 状态与恢复

- 风控确认后立即退出生产池。
- 24 小时、3 天、7 天阶段正确推进。
- 第三次自动复检失败进入人工复核。
- 任意额度正常响应恢复健康。
- 解除隔离和永久禁用语义互不干扰。

### 19.5 存储与前端

- 四种存储后端迁移、读写、筛选一致。
- 桌面端和移动端开关、徽标和操作一致。
- 环境变量锁定开关不能在页面修改。
- 凭证和客户端响应不泄露敏感信息。
